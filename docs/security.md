# PairCode — Security Guidelines & Threat Model

## 1. Security Architecture Principles

PairCode handles untrusted candidate input, executes user-submitted code in multiple programming languages, and facilitates private interviewer assessments. The system is designed following the principle of least privilege, strict defense-in-depth, and zero-trust boundaries between client and backend tiers.

---

## 2. Threat Modeling & Safeguards

### 2.1 Untrusted Code Execution
- **Threat**: Remote Code Execution (RCE) on host servers, lateral network movement, denial of service via fork bombs or infinite loops.
- **Controls**:
  - The Next.js web application and Node.js collaboration service never evaluate, compile, or execute code locally.
  - Code execution is delegated strictly to Judge0 isolated sandboxes (typically running within isolated gVisor/Docker containers with unprivileged namespaces and dropped Linux capabilities).
  - Strict CPU limits (5s), wall-clock timeouts (10s), and memory caps (128MB) are enforced on every sandbox run.
  - Workers do not execute shell scripts or native child processes.

### 2.2 Invitation Token Security
- **Threat**: Invitation URL scraping, brute-force token enumeration, unauthorized participants hijacking interviews.
- **Controls**:
  - Invitation tokens are generated using cryptographically secure random bytes (`crypto.randomBytes(32).toString('hex')`).
  - Raw tokens are never stored in the database. Only their SHA-256 hash (`crypto.createHash('sha256').update(token).digest('hex')`) is persisted.
  - Invitations are valid for 7 days by default (`inviteExpiresAt`) and can be rotated or revoked by the interviewer at any time.
  - The candidate slot is bound to the first authenticated user who accepts the invitation. Future attempts by different accounts to join with that token are rejected with `409 Conflict`.
  - The assigned candidate can reconnect cleanly across sessions.

### 2.3 Role & Access Authorization
- **Threat**: Candidate spoofing interviewer identity to read private notes, start/end interviews, or alter question assignments.
- **Controls**:
  - Roles (`INTERVIEWER` vs `CANDIDATE`) are determined solely by database ownership relations (`interviewerId` vs `candidateId`), never by client-supplied claims or headers.
  - Route handlers check user session identity against the database record before fulfilling requests.
  - Private Interview Notes (`InterviewNote`) are protected by database queries that enforce `interviewerId = currentUserId`. Candidate requests to fetch or modify notes return `403 Forbidden`.

### 2.4 Hidden Test Case Privacy
- **Threat**: Candidate discovering edge-case inputs or expected outputs by inspecting network payloads or DOM state.
- **Controls**:
  - Questions API (`GET /api/questions/[id]`) filters test cases on the server with `where: { isHidden: false }`.
  - Execution result endpoints sanitize `ExecutionCaseResult` records: for cases with `isHidden = true`, `stdout` and `stderr` are stripped to `null`. Only `caseNumber`, `status` (`ACCEPTED` or `WRONG_ANSWER`), and runtime metrics are exposed.

### 2.5 Realtime WebSocket Security
- **Threat**: Unauthorized clients joining WebSocket rooms or eavesdropping on other interview sessions.
- **Controls**:
  - WebSocket connections require a signed JWT generated by `POST /api/interviews/[id]/realtime-token`.
  - JWT is signed using a dedicated secret (`REALTIME_JWT_SECRET`) separate from Clerk credentials.
  - Hocuspocus `onAuthenticate` verifies the signature, expiration, and session ID claims.
  - Cross-room data leakage is impossible because each document is strictly partitioned by `sessionId`.
  - Document writes are blocked if `InterviewSession.status === 'COMPLETED'`.

### 2.6 Input Validation & Payload Size Limits
- **Threat**: Large payload denial-of-service, memory exhaustion attacks.
- **Controls**:
  - Maximum source code length is strictly enforced at 64 KB.
  - Maximum standard input length is capped at 16 KB.
  - All incoming REST payloads are parsed and validated through Zod schemas before hitting business logic.
  - Strict JSON parsing limits in Next.js configuration.
